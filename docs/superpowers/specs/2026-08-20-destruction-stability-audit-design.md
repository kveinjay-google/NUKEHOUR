# 全单位与全建筑销毁稳定性审计设计

## 目标

建立一套可重复、可定位、可在 iPad 真机运行的销毁稳定性测试，逐一覆盖 RA2 规则集中所有可实际生成、具有生命值的单位与建筑。每个对象分别验证普通消失和爆炸死亡路径；任何卡死都必须留下对象名称、Actor ID、死亡类型、死亡武器、当前回调和最后完成阶段。

## 采用方案

采用“静态规则审计 + 真机运行时串行审计 + 故障诊断快照”的组合方案。

- 仅做人工逐项测试无法稳定复现，也无法保证新增对象继续受覆盖。
- 只做 YAML 静态检查不能发现音频、渲染、死亡回调或帧末任务引起的运行时死锁。
- 一次同时炸毁大量对象无法确定具体责任对象，还会把正常瞬时负载误判为卡死。

因此运行时审计一次只测试一个对象，每个阶段完成后才进入下一项。

## 覆盖清单

测试器从当前地图的已解析规则集中自动枚举，而不是维护手写名单。候选对象必须：

1. 名称不是抽象模板；
2. 具有 `IHealthInfo`；
3. 具有可放置位置能力；
4. 是可生产对象、地图可放置对象，或具有单位/建筑占位能力；
5. 能在测试地图找到合法格子。

每个候选对象运行两种场景：

- `BulletDeath`：验证普通死亡、尸体、生成物和消失路径；
- `ExplosionDeath`：验证爆炸武器、爆炸动画、音效、碎片、范围伤害和帧末任务。

对象按名称稳定排序，默认每种场景重复三次。无法在当前地图放置的对象记为 `SKIP`，不得伪装成通过；报告会列出原因，水面对象应在含水测试地图补跑。

## 运行状态机

每项测试严格经历：`prepare -> spawn -> settle-before-kill -> kill-enter -> kill-returned -> settle-effects -> cleanup -> passed`。测试器在进入每一步前同步更新诊断追踪和可刷新的进度文件。

如果主线程卡住，看门狗快照中的最深活动 scope 应显示：对象名称、Actor ID、死亡类型以及具体死亡子系统。若进程崩溃或被系统终止，下次启动仍可从进度文件确认最后一项，而不会丢失证据。

## 诊断增强

为死亡链关键边界加入细粒度 scope：

- `Health.KillNotifications`：逐个记录当前 `INotifyKilled` trait；
- `FireWarheadsOnDeath`：对象、武器、爆炸位置/格子序号；
- `SpawnActorOnDeath`：生成对象与帧末创建；
- `WithDeathAnimation`：图像、序列和效果创建；
- `World.FrameEndTask` 与 `Effect.Tick/Render`：保留最后正在执行的任务或效果类型。

热路径记录只在诊断启用或审计运行时工作，Release 正常游玩不得引入逐帧字符串格式化或明显分配。

## 输出与验收

每次测试生成 `Documents/OpenRA/Logs/DestructionAudit/<run-id>/`：

- `progress.log`：可立即刷新的逐阶段记录；
- `results.csv`：每个对象、场景、轮次、耗时、结果；
- `summary.json`：总数、通过、失败、跳过、最后对象和构建信息；
- 看门狗报告：发生卡死时保存活动 scope 与时间线。

验收条件：静态 YAML 检查通过；配置与清单测试通过；桌面规则/单元测试通过；iOS arm64 Release 构建通过；连接真机时全清单完成且 `failed=0`。若设备未连接，真机项必须明确保留为未执行，不能宣称稳定性已完全验证。

## 范围边界

本阶段只处理死亡、爆炸、尸体/残骸生成和效果清理造成的异常或卡死。不借机重写渲染器、音频引擎或战斗逻辑；发现的根因按独立最小修复处理并加入回归测试。
