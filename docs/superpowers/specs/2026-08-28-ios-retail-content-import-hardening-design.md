# iOS/iPadOS Retail Content Import Hardening Design

Date: 2026-08-28
Status: Recommended design selected and implementation planning authorized by the user
Scope clarification: On 2026-08-30, the user approved a Personal-only release milestone. The publishable target for this milestone is a registered-device Personal Ad Hoc IPA. PublicClean remains a fail-closed diagnostic target until its separately reviewed runtime-resource closure is authorized and completed.

## Goal and release order

Turn the existing iOS/iPadOS Red Alert 2 content importer from a filename-checking prototype into a safe, recoverable importer that produces content capable of starting a real game in the registered-device Personal Ad Hoc build.

The complete pre-game import/readiness gate is unconditional in the Personal build. The compile-time distribution profile controls only which engine/project resources and mod search roots are allowed; it cannot bypass retail archive, map, receipt, profile, or recovery validation. The current PublicClean diagnostic artifact is not launched. Configuration-aware source, metadata, and bundle audits prove that all 17 trusted iOS profile resources are absent, that this absence maps to typed `RuntimeResourcesMissing`, and that no PublicClean edge can reach the Personal importer, catalog, runtime services, wizard, or game graph. This is a static fail-closed contract, not an observed runtime result. A future PublicClean runtime-closure milestone must reintroduce reviewed profile resources and execute the same complete importer/readiness gate before any playable or IPA claim. Desktop startup and its content installer behavior remain unchanged.

Unless a section explicitly discusses PublicClean diagnostics or future PublicClean closure, `first release` and `current milestone` below mean the registered-device Personal Ad Hoc milestone.

The release order is fixed:

1. harden and verify retail-content import, trusted runtime profiles, map validation, and the Personal runtime preflight;
2. finish the Personal iOS About/legal/source surface and its AOT, bundle, signing, and manifest gates, producing the exact final corresponding-source commit locally;
3. only with separate explicit user authorization, publish that exact corresponding source/build material at an immutable public commit/tag URL required by the Personal distribution gate; this source-only prerequisite authorizes no app, IPA, retail data, release asset, marketing claim, or PublicClean publication;
4. produce a registered-device Personal Ad Hoc IPA and prove a fresh-device import reaches a real two-player skirmish;
5. retain PublicClean as a fail-closed diagnostic build that contains no retail bytes, does not increase the frozen historical 580-error delta, and makes no playable or IPA claim;
6. in a future separately reviewed milestone, close PublicClean runtime resources, reintroduce its audited profile resources, and run the same complete importer/readiness and device-skirmish gates;
7. only after that closure, and with separate user authorization, prepare any public app release and matching broader release/tag action beyond the already verified Personal corresponding-source prerequisite.

The source tree may be prepared locally during the earlier stages. The Personal plan performs only read-only verification of a supplied immutable source URL: creating a GitHub repository/remote or pushing/tagging the corresponding-source prerequisite is an external action that requires separate direct user authorization and is not implied by implementation approval. Without that authorization and a verified URL, the Personal artifact remains honestly blocked. No public app/IPA release is authorized before the later PublicClean closure and its own separate approval.

## Current behavior that must not ship in the Personal IPA

The current implementation is not an acceptable Personal release gate:

- it treats the presence of `ra2.mix` and `language.mix` as a complete validation;
- tests accept text files named `.mix` as valid content;
- hashes are calculated but not checked, persisted, or used at startup;
- Base and Yuri buttons run the same full-replacement operation;
- adding Yuri, music, or maps can erase previously valid content;
- all selected directory files are flattened and unrelated files make a full directory selection fail;
- import has no byte progress, active cancellation, single-task lock, or reliable retry;
- required package mount failures are swallowed;
- imported maps are copied to a directory that the game does not read;
- a clean PublicClean bundle still lacks independent runtime resources required to start the RA2 mod, so it remains diagnostic-only and cannot be presented as a release candidate.

The Personal implementation replaces the importer behaviors above rather than adding more filename checks around them. The missing PublicClean runtime resources remain the explicitly deferred, fail-closed boundary described later in this document.

## Considered approaches

### A. Incremental transactional native importer with engine validators — selected

Keep the iOS document picker and native pre-game experience, but split discovery, validation, map conversion, transaction publishing, readiness, and UI state into isolated components. Reuse OpenRA MIX/audio/map parsers rather than the current filename-only catalog.

This preserves the best iOS Files/iCloud/external-drive experience, supports a full installation directory or selected files, and gives the strongest recovery and test boundaries.

### B. Replace the native flow with the desktop `ra2-content` installer mod

This reuses more existing installer actions, but the installer is not touch- or safe-area-ready, cannot currently start reliably in PublicClean, does not own iOS security-scoped URLs, and still lacks the required deep validation. It is not selected.

### C. Require users to prepare one exact archive or folder layout externally

This is smaller to implement but transfers complexity to users, prevents straightforward installation-folder import, and still requires trustworthy validation. It is not selected.

Downloading, embedding, or repackaging retail assets is not an option. The repository contains no legally approved RA2 `Original Demo Assets` package, and the freeware C&C/Red Alert packages cannot be reused as RA2 content.

## Supported sources

The first release supports both choices approved by the user:

- individual extracted retail data files selected in the iOS Files picker;
- a complete extracted Red Alert 2 or Yuri's Revenge installation folder selected in the Files picker.

Supported providers include local Files storage, iCloud Drive, Finder file sharing, and external storage exposed through the system picker. The retail-content source importer itself makes no network request and never uploads selected retail content; this does not prohibit the separately bounded community-map service described below. A Files provider may download a user-selected cloud item under the provider's own system UI and policy. Reads occur through `NSFileCoordinator` or an injectable equivalent while the security scope is held. Provider preparation/materialization is an indeterminate phase with typed unavailable/download-required failures. Unknown-length streams are copied under a running hard byte cap, repeated space checks, and post-copy size/digest verification; a source that changes during the coordinated copy is rejected.

The first release does not directly open ISO images, ZIP/RAR/7z archives, Westwood CAB installers, or The First Decade CAB/HDR media. Selecting one produces a specific localized `extract the installation first` explanation. The existing desktop First Decade manifest bug is tracked separately; it is not presented as working iOS support.

## Content groups

Content is modeled and receipted in independent groups, then batch-committed for each user selection:

| Group | Required files or result | Readiness role |
| --- | --- | --- |
| RA2 Base | `ra2.mix`, `language.mix`, plus their required nested package graph | Required |
| RA2 Music | `theme.mix` | Optional |
| Yuri | `ra2md.mix`, `langmd.mix`, plus their required nested package graph | Optional, all-or-nothing |
| Yuri Music | `thememd.mix` | Optional |
| Maps | At least one safe, converted, loadable multiplayer `.oramap` | Required for a playable launch |

Base speech and audio are validated inside `language.mix -> audio.mix -> audio.bag/audio.idx`; they are not modeled as loose root `audio.bag/audio.idx` files. The existing misleading `Audio` state is replaced by separate Base Music and Yuri Music states.

Yuri content is optional. A partial Yuri pair is reported precisely and is not mounted, but it never disables an already valid RA2 Base installation. Adding Yuri or either music group never requires selecting Base again.

Yuri music is not marked usable merely because `thememd.mix` exists. The RA2 music definitions must be wired and validated to expose the supported Yuri tracks; until then the group remains present-but-unavailable instead of falsely reporting Ready.

### Trusted runtime profiles

The Personal milestone uses two explicit, tested manifest entries inside the same trusted canonical `ra2` package rather than adding a mutable runtime overlay. This runtime profile is conceptually independent from the compile-time Personal/PublicClean distribution profile, but the current PublicClean diagnostic artifact deliberately excludes these unreviewed profile resources. Future PublicClean runtime closure must reintroduce reviewed copies of the same trusted entries rather than inventing a weaker profile:

- `mod.ios-base.yaml` registers only the original RA2 rules, factions, actors, weapons, voices, sequences, and content packages;
- `mod.ios-yuri.yaml` registers the complete RA2 + Yuri's Revenge definition set only after the complete Yuri group validates.

Both entries retain manifest/mod ID `ra2`, use the same package, metadata version, map folders, network identity, and canonical map identity. Imported and converted maps therefore retain `RequiresMod: ra2` and remain compatible when a later launch moves from Base to the complete profile. Desktop startup still reads the unchanged default entry name `mod.yaml` and sees no new selectable mod. The engine accepts an alternate manifest entry only as a trusted root-level filename inside the already selected package, rejects separators/absolute/traversal names, and keeps that choice across same-mod reinitialization. The iOS host maps the closed runtime-profile enum to the two literal entry names; receipts and user input never supply a path or filename.

Each resolved iOS manifest exposes a deterministic runtime-contract ID. Its canonical, versioned byte stream uses fixed UTF-8 encoding and ordinal path order over the selected entry/fragments, every referenced synchronization- or loading-relevant YAML/Fluent/resource contract, filename catalog, and map format. The managed-image identity set is exactly every regular no-follow file that is an immediate child of the finished `.app` root and has a canonical one-segment NFC filename ending in the ordinal lowercase suffix `.dll`; there is no framework-name exclusion. It therefore includes all OpenRA/NukeHour project assemblies—at minimum `OpenRA.Game.dll`, `OpenRA.Mods.Cnc.dll`, `OpenRA.Mods.Common.dll`, `OpenRA.Mods.RA2.dll`, `OpenRA.Platforms.Default.dll`, and `OpenRA.iOS.dll`—plus every shipped framework and third-party managed dependency. A `.dll` in a nested directory, or represented by a directory, symlink, or non-regular entry, is forbidden by the finished-app/IPA audit instead of silently creating a second namespace. For each accepted root image the contract records canonical bundle filename, final SHA-256 and PE module MVID, and it also records the generated AOT-registry/build identity; assembly name/version alone is insufficient. A finished-bundle audit fails on any missing, extra, duplicate, non-managed, or unparseable root `.dll` and on every nested `.dll` path. Changing code or rules behind an unchanged list therefore changes the contract, while a deterministic rebuild from identical inputs produces the same ID. The engine-facing profile string is fixed, not derived from an enum name or user text: Base is `ra2-base`, Yuri is `ra2-yuri`. That profile string plus the full contract digest is written into the active receipt, network/server session handshake, new replay metadata, new save metadata, and profile-scoped skirmish/settings storage. Peers with different digests fail before lobby admission. Saves/replays are listed and loaded only under the exact matching profile/digest; an iOS profiled build hides legacy files with no digest and reports why instead of guessing. The default desktop `mod.yaml` preserves existing legacy persistence behavior. Base-to-Yuri and Yuri-to-Base tests prove maps remain physically shared while incompatible saves, replays, skirmish presets, and peers remain isolated.

For Personal iOS, the exact `OpenRA.iOS.dll` embedded in the reviewed, Apple-code-signed finished application is one trusted composition TCB. `InternalsVisibleTo("OpenRA.iOS")` grants that assembly as a whole access to Game/RA2 internals; it is not a per-type, per-file, or per-call-site CLR boundary, and the assembly is not CLR strong-named. In this document, `unforgeable`, `sole production caller/producer`, and `ordinary code cannot` mean unavailable through the public API to code outside Game/RA2 and this audited TCB. Within the TCB, uniqueness is a release invariant enforced over the complete evaluated compile graph and final IL call graph, then bound to the finished-app/IPA managed-image SHA-256, MVID, generated AOT identity, same-build reference app, and Apple code signature. No untrusted mod or consumer assembly is compiled into or loaded as part of this TCB. Simulator builds prove compilation and behavior only; they are not signed release evidence. Reusing the weak-named engine DLLs with a third-party assembly also named `OpenRA.iOS` in a different application is outside this shipped-app threat model and confers no claim about that other application.

The contract byte schema is fixed rather than implementation-defined: strict NFC UTF-8 strings use unsigned-32 little-endian byte lengths, counts/tags/versions use unsigned-32 little-endian, file lengths use unsigned-64 little-endian, SHA-256 values are decoded raw 32-byte values, and MVIDs are the 16 bytes decoded from lowercase `Guid.ToString("N")` display order rather than platform/.NET memory order. The stream has a fixed magic and schema version, writes profile/selection/fragments/cultures first, then the generated global-ordinal applicable descriptor records, validator/catalog/map versions, ordinal managed images, and AOT identity, with no locale/native-endian/trailing representation. The AOT identity is itself a separate fixed framed SHA-256 over magic/schema plus ordinal type-full-name records containing the Basic/UseCtor tag and metadata-ordered parameter names/canonical generator type expressions; it never hashes generated C# text or reflection enumeration order. Checked literal vectors and independent writers are release gates for both digests.

The sole reviewed resource-shape authority is the checked-in `packaging/ios-runtime-contract-descriptor-shape-v1.json`: schema `1`, exactly `296` byte-sorted descriptors, file SHA-256 `6c0d12b5a985bcf87fc255a03a958dbc09be00de9238b239354c8d34be1bd8f6`, and canonical framed-shape SHA-256 `4fe820475ee4d6ef843320f406b5db3fd414fd106c953b4a7b4a05020fb3614d`. It contains 165 Contract rows and 131 PreflightOnly rows, yielding 277 Base-applicable and 284 Yuri-applicable rows. The project file is a literal 1:1 build projection of that golden, not a second source of membership. Generation adds current regular-file length/hash; source path, length, and hash are excluded from shape identity, while the golden file hash authenticates source mappings. The Personal bundle and final audit cover every row exactly once and never bundle the golden itself. Every descriptor-derived Personal `BundleResource` is an exact byte transport with literal per-item `Optimize=false`; this applies to all 296 rows, including the exact 63 PNG rows, and is transport metadata rather than contract-shape data. The finished `.app` and safely extracted IPA are each rehashed against the generated length/SHA-256 inventory, so a same-pixel PNG re-encoding or any other build transform fails even if project metadata appears correct.

The manifest-side Contract projection is derived rather than copied into another file table. Both iOS profiles declare the one reserved runtime-contract culture `zh-CN`. The engine canonicalizes the selected root, ordered fragments, and every entry in the closed file-bearing manifest arrays through the manifest's exact system-package aliases, then adds the `zh-CN` sibling of every Fluent message file and ordinally deduplicates the result. Only `$id -> mods/id`, `^EngineDir|mods/id -> mods/id`, and current-package-relative mappings are accepted; content/retail aliases, unknown roots, optional markers, path escape, duplicate/case aliases, or an unclassified file-bearing section fail closed. This yields exactly 146 Base and 153 Yuri Contract paths, matching the applicable golden projection without a second hand-maintained membership source. A manifest with no runtime-contract culture—including every legacy/default desktop entry and all other existing mods—keeps an empty projection and does not enter this new alias validator, preserving legacy startup behavior.

The PreflightOnly set deliberately governs the complete mounted `bits`, `uibits`, and fonts directories—including backup or currently unreachable files—as a whole-package closure, plus every renderer shader and fixed startup resources such as root/mod AUTHORS, VERSION, global MIX database, RA2 icon, legacy/profile manifests, blank shell map, and TS manifest dependency. The Contract set always includes all nine Chinese Fluent overrides, independent of the current language. Static preflight derives the same fixed authenticated global-ordinal projection twice from the immutable inventory and manifest (Base 277 or Yuri 284), acquires only those expected canonical names, and finally verifies every retained expected-name lease unchanged. Its descriptor-relative acquire-by-name root does not enumerate or reject unrelated bundle extras; the checked golden plus evaluated source/project and finished `.app`/IPA audits own that closed-set proof. The unselected `ra2-content`/`common-content` installer closure is excluded only because preflight runs after native importer Ready and verified required retail mounts make that fallback unreachable; running preflight earlier is forbidden. Content-only Fluent changes regenerate descriptor length/hash without changing the shape.

Runtime-contract handling has two non-interchangeable stages. Before publication or recovery selection, a pure expected-contract builder authenticates the generated descriptor inventory, resolved manifest projection, managed-image/AOT identity, catalog and validator versions, then computes an expectation only from those immutable recorded values; it has no resource-root input and performs no file open, hash, or unchanged check. Candidate catalogs and receipts may persist only that plain expected contract. After the final retail archive/map candidate has produced the one selected Ready lease, static preflight accepts that exact Store-minted Ready plus the selected lease's opaque validation identity, requires their validation identities to be `ReferenceEquals`, pins and hashes the applicable Contract and PreflightOnly files exactly once under the same already-started deadline, proves their actual bytes and identities equal the generated inventory, and returns a verified-contract wrapper around that exact expectation plus final trusted selection, canonical map-compatibility projection, and the same private binding.

Only that exact wrapper/Ready pair may become engine runtime identity, reconcile/consume pending content, construct contract-bound runtime services, or seal startup. Every consumer first requires `ReferenceEquals(wrapper.Binding, ready.ValidationIdentity)`. Pending mutation has an additional staged authority boundary: Task 7 defines only the private partial authorization/session shape, Task 8 structurally binds current pointer/receipt/entry/reference state without minting authority, and Task 14 performs the sole final one-shot mint after the identity comparison. Every p/t/marker transition consumes a fresh authority into a private session; a verified wrapper, Ready, structural binding, or scalar tuple alone is inert. All scalar profile, selection, compatibility, usage, and identity values are derived internally from the pair. Public values remain handshake data, never startup authority: the profiled state shell, profiled `SealForGame`, and state-taking game entry are internal to Game plus the audited iOS TCB, and the final IL gate permits only the coordinator call edge after exact pair check. A differently named ordinary consumer may construct a scalar but cannot seal or run a profiled startup. The importer never eagerly consumes a pending seal after publish. Repair validation and its single lease-bearing publication never run static preflight; publication failure asynchronously releases provisional retail ownership without consuming pending content or constructing game services.

Desktop `mod.yaml` remains flat and byte-for-byte unchanged. It continues to reference the nine unchanged mixed sources directly—`rules/{world,defaults,proxy-actors,allied-infantry,soviet-infantry,soviet-vehicles}.yaml`, `sequences/{vehicles,voxels}.yaml`, and `audio/voices.yaml`—and never includes a new profile fragment or overlay.

Each iOS root is instead a three-fragment composition with no recursive includes: Base is `manifest/common.yaml` + the complete `manifest/gameplay-base.yaml` + `manifest/filesystem-ios-base.yaml`; Yuri is `manifest/common.yaml` + the complete standalone `manifest/gameplay-yuri.yaml` + `manifest/filesystem-ios-yuri.yaml`. `common.yaml` is the complete ordered semantic equivalent of every desktop node outside the gameplay and filesystem sections. `gameplay-base.yaml` mirrors every desktop gameplay list in order, substitutes exactly nine audited `*-base.yaml` copies for the nine mixed sources, and omits exactly the seven Yuri's Revenge-only whole files: `rules/yuri-{infantry,structures,vehicles,naval}.yaml`, `sequences/yuri-{infantry,structures}.yaml`, and `weapons/yuri.yaml`. `gameplay-yuri.yaml` directly references the nine original mixed sources plus all seven Yuri whole files in the original desktop order. It never loads a Base copy, and Base never loads an original mixed source. There is no Base-plus-Yuri overlay and no `*-yuri.yaml` source; outside the deliberate iOS filesystem/map-folder replacement, the fully resolved Yuri manifest is semantically identical to desktop, including effective node and trait order. Source-of-truth drift tests lock the unchanged desktop bytes, complete ordered lists, Base's closed audited subtraction, and Yuri's resolved desktop equivalence; they also fail if an expansion-only dependency is added to shared `rules/ai.yaml` without review. The original RA2 `yuri` actor and earlier `YuriVoice` remain legitimate Base content.

The current canonical manifest unconditionally parses Yuri's Revenge definitions, so simply omitting optional MIX mounts is not a valid Base profile. A complete validated Yuri group makes the Yuri context eligible but does not select it by itself. Before commit, the fully validated staged import plan tests each final map under every available trusted context, then chooses Yuri only when the complete Yuri group remains valid and at least one final map is Yuri-compatible; otherwise it retains any valid Yuri bytes as inactive optional content, selects Base, and requires at least one Base-compatible map. Only after the whole batch commits does the receipt become authoritative for the next launch. `AppDelegate` accepts only the fixed profile IDs and derives the manifest entry from that verified active receipt; no map, setting, unrestricted command-line value, or user-supplied data can override it.

Both profiles receive independent startup, map-load, sequence-load, lobby-faction, and skirmish tests. The receipt records the profile ID, a digest of the exact manifest contract, canonical mod/map format versions, and the filename-catalog digest in addition to validator versions and file hashes.

### Pre-game engine context

Map conversion and profile validation occur before `Game.InitializeAndRun` through a reusable pre-game context. A shared engine startup helper configures EngineDir and SupportDir once, permits a later request only when the normalized paths are byte-for-byte identical, initializes the settings/key context needed by `ModData`, discovers the fixed bundled mods, and returns an owned no-render `ModData` scope. Normal startup reuses the same directory configuration instead of calling one-shot override APIs again. Different paths, partial initialization, or use after disposal fail closed.

`PreGameModDataScope.TakeOwnership()` is the sole public cross-assembly ownership transfer. A live source atomically moves its exact `ModData` into one fresh scope: exactly one concurrent take wins, all retained source aliases become inert, and a take racing source disposal has one linearized winner so the payload is either transferred or disposed exactly once, never both. Work through a successfully owned scope remains sequential, and every pre-game scope is disposed before normal startup. From Task 3 onward its complete manifest/profile/conversion/validation call graph receives explicit `ModData`, `ObjectCreator`, settings, and loader dependencies and never reads, assigns, saves, restores, or temporarily adapts `Game.ModData`. A throwing global sentinel is mandatory coverage. Any remaining legacy type that cannot operate through those explicit dependencies closes readiness; no scoped-global compatibility escape is authorized.

Instance-scoped game services use separate inert binding, activation, and asynchronous draining ownership. `ModData` first acquires every non-null bind token in registration order and proves every bound service has the exact registered reference identity; binding cannot switch the dispatcher backend, subscribe memory pressure, start a queue, or expose external work. Only then may it activate services in registration order and acquire a separate non-null typed activation token. The dispatcher activates before the runtime-map store. A throwing activation must synchronously self-rollback before propagating. The Game-owned lifecycle dispatch lane is dedicated to that exact ModData and distinct from legacy global `RunAfterTick`/`delayedActions`. During normal operation, every `LogicTick` executes one fixed bounded FIFO batch of admitted lifecycle tickets before advancing world/network state, so minimap uploads, runtime-map commits, and memory-pressure callbacks cannot wait until shutdown; this bounded pump never executes or reenters the legacy action queue. On construction rollback or normal unload, Game first stops gameplay producers, then begins reverse activation drainage. `BeginDrainAsync` synchronously rejects new epoch work and returns an idempotent fence; while the store drains, the dispatcher remains active and Game switches to the isolated drain-until-fence pump. Shutdown order is store activation drain/dispose, `MapCache` preview drain plus direct game-thread sheet/atlas disposal, dispatcher activation drain/dispose, then reverse bind-token disposal and final reverse service disposal. Same-mod reconstruction may replace the legacy queue, unmount, or clear the old ModData only after all three fences/resources and reverse unbind complete. Activation and bind tokens may not synchronously join or wait on workers. This permits an operation already past its non-cancellable durability boundary to execute its reserved game-thread commit exactly once without deadlocking shutdown or losing a ticket during queue replacement.

Cleanup inside the already ordered `ModData` teardown phases is total and preserves one exception-precedence rule. `FileSystem.UnmountAll` snapshots all currently mounted packages it owns, excluding borrowed installed-mod packages, and detaches its complete mount/index state before invoking any package disposal; it then attempts every owned package exactly once in snapshot order and reports only the first cleanup fault after all attempts, so an immediate repeated or reentrant call observes an empty root. `Manifest.Dispose` uses an atomic one-shot gate, attempts every disposable manifest module exactly once in insertion order despite a hostile first or middle module, reports the first fault only after the full pass, and makes every repeated or reentrant call inert. The shared `ModData` rollback core continues through all already defined reverse phases while retaining their first cleanup fault. Construction failure always preserves and rethrows the original primary exception after rollback, regardless of cleanup faults; normal `ModData.Dispose` instead completes total cleanup and then reports the first cleanup fault, and remains inert on every later call even when its first call threw. Deterministic multi-package and multi-module tests lock hostile-first/hostile-middle continuation, exact-once counts, detached/repeat-inert state, constructor-primary priority, and normal-disposal first-fault identity. This cleanup rule does not alter activation-fence sequencing, lifecycle-lane behavior, Game drain, `DrainLifecycleDispatchUntil`, or its untimed-wake contract.

Candidate validation never points SupportDir at staging and never changes the active catalog. The importer builds a read-only candidate package that maps each canonical logical filename to either the preserved active file or the validated staged replacement. During candidate `ModData` construction, a scoped loader factory mounts only that closed package at the manifest's `content` mount point; all other format loaders are delegated unchanged. The mapping rejects duplicate/unknown names and paths outside the active or current transaction roots. The scoped loader and candidate package are disposed before commit and the normal loader is restored in `finally`.

Committed retail content and maps live in private, immutable, transaction-generation directories under Application Support, not in the user-visible Documents support tree. The atomic catalog pointer selects one generation; generation contents are never edited in place. After cold hashing and contract validation, the startup gate constructs an active-catalog view from verified open file identities/handles and exposes only the exact receipted archive and map names. Active-content handle, factory, concrete lease, open-result, and opener types are internal to the RA2/iOS friend boundary, and the iOS no-follow descriptor factory is the sole audited production factory inside the trusted TCB. Engine map-entry sources, entry creation, publisher construction, and publisher mutation are also internal; two narrow iOS bridges are the sole audited production call edges on behalf of RA2 retail/runtime stores. Here `narrow` describes the reviewed evaluated-source and final-IL call graph, not friend visibility within `OpenRA.iOS`; no broad Game→RA2 friend or public publisher/result factory exists. The opener retains every descriptor through its sole SHA-256 pass and, immediately before Ready/publication, calls `VerifyUnchanged` on every retained handle; path/descriptor/type/length/stability drift is operationally inconclusive and cannot authorize recovery mutation or Ready. Every authenticated recovery snapshot carries one fresh store-minted, non-persistent validation identity. Ready requires the exact same object on the snapshot, asynchronously owned validation lease, and store-minted Ready capability. Publisher construction plus initial publication occur atomically inside one admitted game-thread bridge action; dispatch rejection creates no publisher. Provisional/failed owners are asynchronously released and awaited before their recovery lock or dispatcher owner is released, while the final mounted owner is disposed directly on the game thread during the ordered Game shutdown ledger. Ready packages and streams duplicate only pinned descriptors and never reopen by path. The normal iOS filesystem loader mounts this view instead of the raw generation or `Content/ra2` directory.

Desktop `mod.yaml` remains byte-for-byte unchanged, including `MapFolders` entries `ra2|maps: System` and raw `~^SupportDir|maps/ra2/{DEV_VERSION}: User`. Both iOS manifests instead use exactly `ra2|maps: System` plus `content|maps: User`; neither contains a raw SupportDir-backed User folder. The active catalog's immutable `content` package owns the read-only `maps` child, but a profiled iOS `MapCache` treats this exact row only as the stable read-only `User` location identity: it does not enumerate the child package, reopen maps, calculate UIDs, or parse metadata through the legacy MapFolders path. The bound verified snapshot provider is the only source of retail map entries and supplies their already validated immutable metadata once. Legacy desktop MapFolders retain their existing scan behavior. Thus only receipted maps in the verified catalog appear as User maps, without a second parse or duplicate budget charge. Legacy maps, hand-copied maps, raw support-directory maps, unreceipted files, stale epochs, quarantined optional groups, symlinks, and files replaced after verification are invisible. The validated view remains alive for the lifetime of `ModData` and is disposed only after unmount. The Personal build uses this rule now; a future runtime-closed PublicClean build must use the identical rule before it can construct the importer.

Existing flat iOS content under the legacy Documents `Content/ra2` and user-map locations is never trusted or mounted directly. On first upgraded launch it is presented as a legacy migration candidate, copied through the same bounded staging/hash/structure/map validation pipeline, and activated only by a successful generation transaction. The previous files remain untouched until the new generation commits; unrelated or invalid legacy files are reported and left unmounted. Migration failure preserves both the legacy bytes and any previously valid generation.

## Definition of Ready

`Ready to Play` is stronger than `files copied`.

RA2 Base is ready only when all of the following are true:

1. both required top-level MIX files are present in the active content store;
2. they parse through the real OpenRA MIX loader;
3. every mandatory nested package declared by the active RA2 manifest can be resolved and mounted;
4. the BAG/IDX pair inside the nested audio packages validates;
5. a cold-start SHA-256 pass over every Base archive and every candidate published map matches its group receipt, while invalid optional groups/maps are isolated rather than exposed;
6. at least one map passes conversion, safety checks, supported-format loading, rules loading, and spawn validation under the Base profile;
7. the selected Base runtime profile loads without referencing Yuri-only content;
8. the current distribution profile's runtime-resource preflight reports that the engine-owned/project-owned side of the mod is present and mountable.

Only the Personal artifact may reach or advertise this Ready state in the current milestone. The current PublicClean artifact is not launched; source/configuration and bundle audits prove that its absent fixed profile resources map to `RuntimeResourcesMissing` and that the Personal startup graph is unreachable. This static contract is not evidence that the code was observed at runtime and is not evidence that PublicClean is Ready.

At least one launchable Base-compatible map must support a real skirmish with two or more player spawns. Mission-only maps, Yuri-only maps, and maps that parse but cannot create a playable Base lobby do not satisfy the Base gate.

Yuri activation is Ready only when Base is Ready, both Yuri archives pass their complete nested-package checks, and at least one final map is Yuri-compatible. A valid Yuri pair without such a map is retained as authenticated inactive optional content but reported Unavailable until a later transaction supplies a compatible map; it never produces an empty Yuri map view. Music readiness never controls Base launch readiness. A cold-start failure in Yuri, either music group, or one map marks only that optional group/item Invalid/Unavailable and excludes it from the active-catalog view. If Base plus at least one Base-compatible map still validate, the gate selects Base and permits launch while a journaled repair generation quarantines or deactivates the invalid optional data; it never deletes active files in place. A Base archive failure or loss of every Base-compatible map remains blocking.

V1 has no reviewed retail fingerprint catalog, so its trusted edition-code closed set is empty. Structurally complete retail content may be accepted only as `Compatible, unrecognized edition`; V1 never emits `Recognized` and rejects every non-null recognized-edition code in a receipt. Adding a recognized edition later requires a separately reviewed fingerprint catalog, a schema/validator version change, and new literal tests; accepting a new string under schema 1 is forbidden. Hash recognition is never a substitute for structural validation.

## Source discovery and selection safety

A platform-neutral discovery service receives explicit selections from the iOS picker and emits a deterministic import plan.

- Direct file selections and files discovered under a selected directory are distinguished.
- Directory traversal examines regular files only, does not follow symlinks, and applies explicit depth, entry-count, and total-byte limits large enough for a normal installation but bounded against provider loops or denial of service.
- Recognized retail basenames and supported map extensions become candidates.
- Unrelated files inside a selected installation directory, including executables, DLLs, configuration files, text files, and uninstallers, are ignored and summarized; they are never copied or executed.
- Directly selecting executable content is a specific error.
- Directly selecting an unsupported archive or installer is a specific `extract first` error.
- Directory enumeration and cloud-provider access errors become recoverable results; they cannot escape an `async void` callback.
- Full user paths and cloud-account identifiers never appear in UI, telemetry, or ordinary logs.

Candidates are classified into content groups before any active content is changed. A same-name/same-hash candidate is deduplicated. Same-name/different-hash retail archives are a conflict and require a new selection; the importer never silently chooses or overwrites one. Converted maps use content digests for identity so equal maps deduplicate and different maps with the same display name can coexist safely.

## Validation pipeline

Validation proceeds through explicit phases:

1. discover and classify candidates;
2. calculate the copy plan and required temporary space;
3. copy candidates into a unique staging transaction while computing SHA-256;
4. re-read staged size and digest;
5. run bounded envelope validation before any existing MIX, IDX/BAG, or ZIP loader sees untrusted input;
6. parse top-level and nested MIX archives with hardened OpenRA loaders;
7. validate required nested package names against the candidate profile manifest contract;
8. validate BAG/IDX relationships and readable audio indexes;
9. select the candidate Base or Yuri profile, prove its restricted required mounts, and compute its pure expected runtime-contract digest without opening distribution resources;
10. discover, convert, safely copy, and load maps under that candidate profile;
11. run final candidate readiness against the expected contract, without static runtime-resource preflight;
12. prepare deterministic group receipts, catalog, and a complete proposed immutable generation;
13. revalidate the proposed generation's profile, required mounts, maps, contract, receipts, and readiness, then durably mark it `Prepared`;
14. atomically publish the complete affected batch by switching the generation pointer;
15. reopen and verify the selected active generation; any post-switch failure enters mandatory recovery and restores the complete previous generation rather than accepting a partially valid active view.
16. only after one final Ready retail lease exists, run the one static runtime-resource preflight and obtain the verified contract required to seal game startup.

The validator does not depend on mutable global UI state. Its inputs are an immutable import plan, explicit manifest contract, explicit destination roots, validator version, and cancellation/progress interfaces.

Tests use project-generated synthetic MIX, BAG/IDX, and map fixtures containing no Electronic Arts data. A private opt-in integration fixture may point to a legally owned local installation, but its files, paths, hashes, and derived assets never enter Git or public artifacts.

The bounded envelope policy is versioned and checked before allocating from untrusted counts or declared sizes. It uses checked arithmetic and hard limits for source bytes, nested depth, entry counts, index bytes, individual and aggregate expanded bytes, normalized-name/hash uniqueness, compression ratio, elapsed time, and cancellation. IDX validation proves its header/count table fits the real file, bounds the sound count, validates unique legal names and fields, and proves every BAG `offset + length` is inside the BAG. ZIP validation parses the central directory before the existing loader, rejects unknown/negative/inconsistent sizes, duplicate normalized paths, traversal, unsupported entry types, and expansion bombs. The hardened runtime loaders map truncated input, overflow, out-of-memory guards, and invalid offsets to typed corruption errors rather than swallowing them.

## Map discovery and conversion

The importer automatically discovers supported multiplayer maps in the selected directory and in map-bearing packages exposed by validated retail archives. It also accepts separately selected `.map`, `.mpr`, `.yrm`, and `.oramap` files.

The large utility-only RA2 map command is refactored into a reusable conversion service with explicit dependencies. The CLI command becomes a thin adapter over the same service. The target conversion API does not read `Game.ModData` as an implicit global; it receives a restricted map-import context containing the current manifest, terrain data, rules, and output package factory.

A bootstrap validation context initializes only the engine/project data required to convert and load maps before `Game.InitializeAndRun`. It does not enter the RA2 main menu or create a game world. EngineDir and SupportDir bootstrap is idempotent for the same resolved paths, and the normal game startup reuses rather than conflicts with that initialization. Every conversion/load dependency is explicit; no code on this path may touch `Game.ModData`, even through a sequential save/set/restore adapter. If an OpenRA type still requires that implicit global, the context cannot be initialized, map readiness is unavailable, and the startup gate remains closed.

Traditional `.map`, `.mpr`, and `.yrm` sources enter the RA2 conversion service. A direct `.oramap` is not converted: it first passes the bounded ZIP/package envelope and an exact current-format root-file allowlist (`map.yaml`, `map.bin`, and optional `map.png`), then enters the same post-conversion map validation used for generated output. Any other entry, subdirectory, symlink, duplicate normalized name, embedded script, or custom data file is rejected. The validator bounds raw YAML bytes, line/scalar sizes, indentation depth, node count, and parsed object counts before calling `MiniYaml`; it preflights PNG signature, IHDR, dimensions, checked decoded stride/size, chunk count, aggregate IDAT bytes, and secondary inflate ratio before calling `Png`. The shared `Png` implementation and MIX content accessors are hardened with the same checked allocation guards so no other call site can reintroduce unchecked `Width * Height * stride` or `uint`-to-`int` allocation.

For every traditional candidate the conversion path:

- validates source size and format before allocating large buffers;
- converts into a unique staging output;
- applies the modern Gen2 map cordon/padding rules instead of the legacy RA2 utility bounds;
- treats unknown tiles, unsupported actors, invalid compressed lengths, impossible dimensions, and duplicate spawn definitions as explicit diagnostics instead of silently replacing data;
- rejects executable content, scripts, assemblies, native bundles, path traversal, duplicate package entries, symlinks, and unsupported embedded content;
- reads the legacy `MultiplayerOnly` source flag and rejects source maps that are not multiplayer candidates;
- emits the current map format, canonical `RequiresMod: ra2`, and `MapVisibility.Lobby`;
- loads the converted map, metadata, terrain, rules, and player definitions;
- requires a supported theater; unsupported Yuri theaters do not block an already valid Base map set;
- requires at least two valid multiplayer spawn points;
- writes only into the current transaction's staged map root and publishes it through the verified catalog-backed `MapFolders` package;
- keeps an existing valid map when a replacement or conversion fails.

Before constructing an OpenRA `Map`, both converted and direct `.oramap` metadata are parsed independently and rejected if any custom `Rules`, `Weapons`, `Voices`, `Sequences`, `ModelSequences`, `Music`, `Notifications`, or `FluentMessages` data is present. After construction the validator requires exact Lobby visibility, `InvalidCustomRules == false`, zero replaced invalid terrain tiles, valid bounded actors/owners/players, unique in-bounds spawn points, canonical mod compatibility, and successful current rules/terrain loading. A shell-map-only, mission-selector-only, hidden, or loader-fallback map does not satisfy readiness. Validation decodes at most one preview under the per-map budget and releases its CPU buffer before advancing. Untrusted map strings use a per-map bounded interner and only bounded immutable display metadata crosses into the catalog; they never enter the existing unbounded global `MapCache.StringPool`. Every map is tested independently in both trusted contexts when the required assets exist, and its receipt records closed `CompatibleProfiles` flags. The Base active view exposes only Base-compatible maps; the Yuri view may expose Base-compatible and Yuri-only maps. A catalog can never become Ready unless at least one map is Base-compatible, so later Yuri damage can still degrade safely to Base.

Resident-map accounting has two deliberately independent owners. The RA2 receipt domain ships `RetailMapResidentUsageMeterV1` before the engine-entry work and uses it whenever a retail receipt is written or decoded. The engine domain later ships `VerifiedMapResidentUsageMeter` and uses it whenever a verified map entry is created. Both implement the same frozen `NHRM` schema 1 byte stream over map format plus every retained validated metadata field, including MapSize, Bounds, every player field, allies/enemies, and ordered spawns. Fixed-width values are canonical little-endian, booleans are `0|1`, strings use presence plus unsigned-32 strict-UTF-8 byte length, and arrays use unsigned-32 counts. Metadata bytes are the exact checked framed length; string bytes and entries count ordinal-unique present strings in traversal order. The RA2 validator runs both independent meters after projecting into engine metadata and requires exact three-counter equality; callers never supply trusted counters, and neither assembly's meter depends on the other.

Normal `MapCache` enumeration is metadata-first and does not eagerly decode every preview image. The 4,096-pixel PNG edge is only a safe decode ceiling, never an atlas-upload size. Preview PNGs are decoded on demand through a byte-accounted CPU LRU, converted with checked arithmetic into an aspect-preserving thumbnail no larger than 1,024 by 1,024, uploaded through a separately byte-accounted GPU atlas, and the source CPU `Png.Data` buffer is released after conversion/upload unless the thumbnail remains within the LRU budget. The preferred atlas page is 2,048 pixels with a one-pixel margin; creation first proves the page does not exceed the device maximum texture size and every upload proves `thumbnail edge + 2 * margin <= page edge`. On a smaller supported page the thumbnail ceiling is reduced to `page edge - 2 * margin`; if allocation, conversion, or upload still cannot satisfy the checked bounds, the UI uses a fixed bundled placeholder while the validated map remains playable. `SheetBuilder` is hardened to reject any rectangle outside its page rather than relying on callers. Entries with live UI/game references are pinned; cache pressure or an iOS memory warning evicts only unpinned previews and regenerates them later from the verified immutable handle. Catalog planning rejects excess map count, compressed storage, resident metadata, or string budgets before pointer publication, so 256 individually legal worst-case maps cannot multiply into unbounded resident memory.

The converter records source and output digests in the receipt but does not log or publish the retail source path. The final logical map destination is the new generation's catalog map package, whose version/identity is derived from the canonical manifest contract; conversion never writes into the currently mounted `MapFolders` package or a hard-coded `{DEV_VERSION}` directory. Map failures are reported per map; one bad optional map does not erase other valid maps.

MIX indexes contain hashes rather than reliable filenames. Embedded-map discovery uses a versioned, audited RA2/YR filename catalog together with any valid `local mix database.dat` found in the archive. It never brute-forces hashes. Recursion depth, entry count, aggregate uncompressed bytes, compression ratio, and processing time are bounded. If the existing `global mix database.dat` is used, its pinned OpenRA source, digest, and distribution classification must be recorded; otherwise a minimal project-owned resolver replaces it.

### Verified community-map downloads

The prohibition on downloading retail/Demo assets does not remove the existing community-map download feature. When map downloading is enabled by the fixed distribution policy, iOS routes `MapPreview.Install` through a `VerifiedRuntimeMapStore` instead of asking the read-only catalog package for `IReadWritePackage`.

Remote discovery is also placed behind a `VerifiedRemoteMapMetadataClient`; hardening does not begin only after the binary download starts. The client applies the V1 response, request-count, record, line, indentation, node, field, scalar, collection, encoded-byte, decoded-byte, PNG, cancellation, and timeout limits before constructing any `MiniYaml`, Base64 buffer, `Png`, player list, rule object, or preview. A byte scanner recognizes only the exact `minimap`, `players_block`, and `rules` binary-field keys at the expected record depth. Those lines have the separate 2.25 MiB raw-line ceiling so a 2 MiB encoded value plus bounded key/indentation syntax is reachable; every other line remains under 64 KiB. The scanner removes all three fields before `MiniYaml`: `rules` and `players_block` are ignored on iOS, while `minimap` alone is decoded through the 2 MiB encoded/1.5 MiB compressed limits and then the remote PNG envelope. Lookalike keys, duplicate binary fields, invalid indentation, or a binary field at another depth reject the record. The client accepts only canonical UIDs that were present in that exact request and a closed allowlist of basic display fields. iOS never decodes or applies remote custom-rules payloads; a remote result remains non-authoritative display metadata until its downloaded package passes the full local validator. Parsing occurs off the game thread, but the bounded immutable result is committed to UI/`MapCache` state only on the game thread.

The store streams the response to a random same-volume temporary file under the V1 compressed-byte and time limits, reports real received/declared byte progress when a trustworthy denominator exists, and ignores `Content-Disposition` as a filesystem name. The only final logical name is derived from the requested canonical map UID. Before publication it applies the exact `.oramap` envelope/file allowlist, rejects custom rules/scripts, constructs the map under the current explicit profile context, requires Lobby visibility and profile compatibility, recomputes the actual UID, and requires it to equal the requested UID. It then publishes through its own immutable generation/pointer and adds the validated package to the composed runtime map view; the current `MapCache` preview is updated only after that success. Incomplete, oversized, UID-mismatched, invalid, cancelled, or interrupted downloads remain invisible and preserve the previous view.

The retail active catalog and filesystem mounts remain immutable for the entire loaded-mod lifetime. `VerifiedRuntimeMapStore` is the sole, narrow exception: it never changes the retail mount set, profile, runtime-contract ID, or `Game.ModData`. On the game thread it atomically replaces a dedicated immutable runtime-map snapshot consumed by `MapCache`. The previous snapshot, generation, package handles, and streams remain alive until every `MapPreview`/`MapCache` reference releases them; garbage collection is delayed and lock-protected. The store has its own serialized download queue, per-request cancellation token, checksummed generation receipt and pointer, cold-start full-hash validation, crash recovery, and orphan cleanup. Concurrent requests for the same UID coalesce; different UIDs are queued only within the fixed count and staging-byte budgets. Before download and again before pointer swap, it reserves the current-generation, retained-rollback, staging, catalog-count, preview-cache, and disk-safety budgets. At quota it evicts only unpinned, non-current, re-downloadable maps from an old generation; it never evicts the selected map, the last verified snapshot, or a generation with a live handle. If safe eviction cannot satisfy the budget, the request fails with a localized quota error and leaves the view unchanged. A failed recovery keeps the last verified runtime snapshot or exposes no downloaded maps, never a partially published generation.

Runtime-downloaded maps never count toward initial Base Ready, so a fresh install still requires one imported Base-compatible map. They use the same backup-exclusion/file-protection policy and are partitioned by runtime-contract ID. The existing map-readiness publisher continues to report Downloading, Validating, Ready, and failure reason/progress, and every start path remains blocked until the requested map reaches Ready. iOS editor save/delete actions that require a raw writable MapFolder are hidden unless and until they are explicitly adapted to the verified store.

## Transaction, recovery, and receipts

Only one import transaction may own a retail importer root across all processes. The store takes a non-blocking operating-system advisory lock on the fixed no-follow `import.lock` regular file before any provider read, staging cleanup, recovery mutation, generation materialization, pending mutation, or publication; it holds the descriptor-backed lease through the complete operation and releases it exactly once. Acquisition returns a closed `Acquired|Busy|Failed` result rather than a boolean/out lease. Only a successful native/nonsharing-handle acquisition can create the private token that binds the exact pinned root identity and one nonzero acquisition epoch, privately mints one fresh opaque `RetailImportOperationIdentity`, and mints one lease owning that identity; there is no independent identity or lease factory. Validator/repair receives only a borrowed reference from that exact lease, and Prepare requires `ReferenceEquals` between the wrapper-bound identity and the lease-owned identity before I/O. Store construction rejects a lock/storage root-identity mismatch, and every Task 7-added inspect/enumerate/read/create/write/move/quarantine/purge/free-space/pin/reset operation rejects a missing, disposed, wrong-root, wrong-lock, wrong-epoch, or wrong-operation lease before I/O. A second request or process is rejected before it can clean or reuse another transaction's staging directory. This is not an in-memory semaphore, queued wait, path-derived lock name, forgeable caller token, or value-equal root substitution.

Each content group is staged and validated independently, but every group affected by one user selection is published as one batch. The validator first constructs and verifies the complete resulting catalog, including preserved active groups and maps. If replacing Base, adding Yuri, or changing maps would leave that resulting catalog without a valid required profile and at least one compatible playable map, nothing from that selection is activated.

Staging, immutable generations, pointer, journal, and receipts live on the same filesystem volume. A new generation is built under an unreferenced unique directory by copying or filesystem-cloning preserved verified files (never hard-linking or editing them) and moving validated staged replacements/maps into their canonical generation paths. V1 generation IDs are exactly `g-{epoch:D20}-{guid:N}`, commit IDs are `c-{guid:N}`, and pending IDs are `p-{guid:N}`. The epoch is a nonnegative signed 64-bit value rendered as exactly 20 decimal digits and must equal its separately authenticated field; each GUID token is one nonzero GUID rendered as 32 lowercase hexadecimal characters without braces or internal hyphens. Publishing uses a journal with a transaction epoch, the previous generation ID, the proposed generation ID, and only closed group enums plus canonical relative filenames. Pointer, journal, catalog, receipt, and pending-seal documents all use the `NHRI` envelope: four magic bytes, one kind byte, four-byte little-endian schema, eight-byte little-endian payload length, strict bounded payload, and SHA-256 over header plus payload. Schema 1 admits only `ActiveGenerationPointer=1`, `PublishJournal=2`, `GenerationCatalog=3`, `GenerationReceipt=4`, and `PendingSeal=5`, with a 128 MiB payload-only cap. Schema zero, unknown schema-1 kinds, malformed/trailing/current data, and over-limit declarations are corruption; schema greater than one is `UpdateRequired` before kind or payload parsing. Absolute paths, empty components, alternate separators, `.`/`..`, symlinks, and unknown states fail closed. These files are written to unique temporary files, flushed to stable storage, atomically renamed, and followed by the platform metadata/directory durability operation before the next state transition.

The V1 retail-generation store has one exact fixed-root layout. The only immediate-root literals are `import.lock`, `active.ptr`, `publish.journal`, `generations`, `quarantine`, and `pending`. A generation ID validated against its separately authenticated epoch selects exactly `generations/{generationId}`. Its immutable payload root is exactly `generations/{generationId}/content`; its metadata files are exactly `generations/{generationId}/catalog.bin` and `generations/{generationId}/receipts.bin`; and a catalog artifact is stored only at `generations/{generationId}/content/{CanonicalGenerationRelativePath}`. Quarantine entries use only adapter-chosen `quarantine/q-{nonzero-guid-N}`, where the suffix is exactly 32 lowercase hexadecimal characters; no caller-facing q factory exists. Task 8's complete reserved layout is `pending/items/s-{guid:N}/content/{CanonicalStagedRelativePath}` plus the finalizer-only `pending/items/s-{guid:N}/seal.bin` for partial staging; `pending/items/p-{guid:N}/content/{CanonicalStagedRelativePath}` plus `pending/items/p-{guid:N}/seal.bin` for sealed retry data; `pending/items/t-{guid:N}` for the same-nonce tombstone; and fixed documents `pending/consume.marker` and `pending/legacy-migration.marker`. Every GUID is nonzero lowercase `N` form. Private-constructor V1 path tokens mint these paths from the exact private payload `(kind, exactGenerationId, exactEpoch, exactNonce, exactCanonicalRelativePath)`; staging-seal and sealed-seal are distinct root-domain kinds, each named factory enforces its closed null/zero/nonzero component matrix, and `Kind` is the only exposed component/root-domain tag. No token exposes `CanonicalRelativePath` or another general path/component getter, and no persisted journal, pointer, receipt, catalog, caller string, absolute path, decoded corrupt byte sequence, or second root may supply another component, filename, lock, marker, pending item, or quarantine destination.

The fixed-root adapter owns all Task 7 filesystem authority. Inspection is typed `Missing|RegularFile|Directory|Invalid|Failed`; only present states own an opaque entry, and entries expose only their kind plus authenticated generation or pending-item identity—not a filename/path/parent/root/descriptor/inode. Enumeration is deterministic, one-level, and allowed only for generations, inner quarantine, or pending items; one unsafe/unrecognized child fails the whole result. The operation matrix is closed: only named tokens may be inspected/opened/created/written, materialization targets only generation or partial-staging artifacts, and no destructive method accepts a bare `(lease, entry)`, `(lease, decoded marker)`, ordinary capability, path, filename, or DTO.

`FinalizePendingStaging` re-enumerates and pins one same-nonce `s-*`, validates every canonical row/length/hash, writes and fsyncs its seal, fires the Task 7-owned seal-flushed boundary, reopens/decodes/verifies it unchanged, privately mints the sole complete-staging capability, and fires the authenticated boundary. That capability must atomically `TryConsumeFor` the exact root/lease/operation into a private session before the adapter may rename the whole directory `s -> p`; the adapter fires distinct rename and parent-sync boundaries internally. A visible p is therefore never missing its seal, and Task 8 cannot counterfeit an internal boundary by calling a dispatcher after return.

Every live fixed-document or generation quarantine first requires Store to mint `RetailQuarantineAuthorization`. The token binds the exact Store/root/live lease/acquisition epoch/operation identity/source-entry reference/name/inode/kind, closed recovery-or-GC reason and eligibility, plus the complete authenticated active/pointer/journal/pending-receipt/pin/reference set. Its atomic `TryConsumeFor` creates the sole private quarantine session accepted by the adapter; the adapter alone chooses q, renames, syncs both parents, and returns a distinct quarantined-entry cap. That cap must atomically create its own purge session. A crash-left q uses a separately Store-minted recovery authorization/session after a fresh complete-reference-set proof. Ordinary entries cannot enter q, remint q, or purge q.

Pending cleanup and consumption are nominally separate even though both use the crash-stable `t-{nonce}` grammar. Store may mint cleanup authorization for only an exact incomplete s, malformed/invalid p, valid expired/orphan/confirmed-discard p, or crash-left cleanup t after a complete active/pointer/journal/receipt/seal/pin/reference-set census proves it unreferenced and not covered by an authenticated consumption marker. Cleanup s or p moves to same-nonce t only through its private session and yields a cleanup-only tombstone cap; a crash after rename requires fresh full-reference-set reauthorization before remint. Neither cap/session can enter consumption.

Consumption p-to-t, crash-left consumption-t remint, Prepared-with-both-p-and-t-missing commit recovery, and every consumption-marker clear each require a new Ready-plus-verified-contract pair-bound one-shot authorization. Task 7 declares its private partial shape and sessions but has zero production final mint. Task 8 may create only a nonauthorizing structural binding after it reauthenticates exact Ready reference/validation identity, pointer, receipt, p/t/marker inode or exact missing-entry census, profile, contract, selection, transaction and complete reference set. Task 14 is the sole final mint: it first requires `ReferenceEquals(verified.Binding, ready.ValidationIdentity)`, then consumes a structural binding holding that same Ready. Task 7 and Task 8 final-authorization `newobj` counts are zero; Task 14's is exactly one. Initial consumption writes the pair-bound Prepared marker and performs p-to-t rename plus parent sync inside the adapter session. Its returned consumption tombstone has a separate purge/Consumed session. Crash remint, missing-t commit, and marker authentication atomically consume both a fresh pair authorization and one canonical decoded-pinned proof; marker clear additionally consumes the returned authenticated-marker cap into its own private session. There is no bare lease+entry+decoded mutation API.

Legacy-migration marker clear is not pair-authorized but is equally closed: Store mints a separate one-shot authority bound to the fixed marker inode, exact lease/root/operation, authenticated completed-migration state and complete reference set. It must atomically consume the canonical decoded-pinned legacy proof into the same private marker-authentication session, then the authenticated-marker cap creates the only clear session. It grants no p/t consumption or cleanup authority.

Task 7 defines an independently compilable partial marker codec whose nested decoded proof has a private constructor and owns the pinned file; Task 8 adds the sole canonical `DecodePinned` and sole production proof construction after full codec validation. A plain pinned file, decoded DTO, forged/replayed/drifted proof, structural binding, wrong Ready/verified pair, or second use has no mutation bridge. Every authorization, wrapper, cap and private token—including quarantine, reset, complete staging, quarantined entry, cleanup/consumption tombstones, authenticated marker, quarantined root and final pair authority—atomically flips once in `TryConsumeFor` while constructing its exact private session; failed matching does not consume an unrelated owner. All aliases become inert after success and dispose idempotently.

Task 7 also owns both typed failpoint families and dispatchers in `RetailImportFaultInjection.cs` plus every Hit site in Store/FS; Task 8 only constructs and injects the pending dispatcher. Task 8 uses this already-reserved surface and never raw `System.IO` or Task 6's legacy string methods. The adapter also provides no-follow pinned regular-file reads, streamed create-new materialization with checked expected length and SHA-256, descriptor-rooted free-space queries, and independently retained root/generation/file/stream pins. Large retail artifacts are never converted to one `byte[]`. A materialization consumes a caller-owned verified stream, checks the unchanged original validation deadline and clock during every bounded copy/hash chunk, fsyncs and applies/verifies storage policy before exposing its entry capability, and removes only its own unpublished temporary inode on failure. Disposing an outer store prevents new acquisitions but cannot invalidate an existing pin or stream; the final reference closes the descriptor exactly once. A live generation, snapshot, handle, package, stream, root pin, or retained pin prevents quarantine, garbage collection, and purge. Process-lock, active, journal-referenced, pinned, cross-root/volume, wrong-kind/nonce, self/descendant, decode bypass, transaction/reference-set drift, or identity drift fails before mutation. The decoded marker proof's private state includes its fixed token, owned pin, schema/digest, and canonical document-kind/state/pending-ID/generation-ID/epoch/commit tuple. It exposes no semantic getter or delegate. Every component is resolved from a pinned parent only after raw enumeration proves the exact ordinal UTF-8 spelling and absence of a distinct `OrdinalIgnoreCase` alias, both before and after create/rename; outer leaf/reset lock/marker, inner lock, fixed literals, and token paths all fail closed on a case alias. Task 7 owns the needed native link-count/identity wrapper in its filesystem/process-lock implementation and does not change Task 6's frozen native identity. Recursive purge classifies each child no-follow: only a verified directory recurses, while symlinks and other non-directories are unlinked as entries without following targets, so partial reset cannot stall and outside sentinels remain unchanged. Platform tests cover Darwin/Linux/Windows where supported, with an explicit capability gate or synthetic adapter for case-fold/link behavior unavailable on the host volume.

Copied-but-not-yet-validated data uses a separate non-authoritative `PendingValidation` snapshot whose sole persisted authority is the schema-1 `PendingSeal` document. The group must match the closed basename classifier; each length is no greater than the 2 GiB per-source cap; paths are relative only to the sealed transaction root and unique; retained non-map basenames and retained map digests obey the same uniqueness rules as the staged plan. Expiry is not serialized: it is derived as seal time plus exactly seven days, with non-UTC, future/rollback, and arithmetic-overflow cases failing closed. No picker/provider/account path, security-scoped URL, original `RetailSourceId`, `RetailCandidatePlan`, or caller root is persisted. Resume creates only deterministic in-memory synthetic source IDs `sealed/{ordinal:D4}/{SafeBasename}` and never treats them as original identity. The snapshot is not a publish journal state and cannot select a runtime profile. Cold startup always resolves a real publish journal first, then may validate a complete pending snapshot; only successful candidate/profile/map validation creates `Prepared`. A complete sealed snapshot no longer depends on its original security-scoped URL. Only an incomplete copy is invalidated by lost source access. A failed pending snapshot never changes the active pointer and may enter cleanup only through Store's full-reference-set authorization. Every attempt that exposes bytes under `p-{nonce}` carries non-null `SourcePendingId=p-{same nonce}` through sealed source, validated wrapper, prepared state, every journal state, and receipt; null is legal only for a direct attempt that never creates s or p. Publishing persists that ID but does not consume the seal.

Consumption/reconciliation is legal only after a new final-readiness attempt holds the exact current Store-minted Ready and matching verified-contract wrapper. Task 8 first creates a nonauthorizing structural binding; Task 14 then requires their binding identities to be `ReferenceEquals` and performs the unique final mint. The resulting one-shot authority is rechecked against current pointer, receipt, pending inode, generation, epoch, commit, profile, contract, selection and complete reference set before one private session is created. A mismatch or preflight failure leaves pending/marker/tombstone bytes unchanged. Every consumption-marker clear first opens the exact fixed token, transfers its owned pinned file into canonical Task 8 decode, atomically combines the nested proof with a fresh final pair authorization, and then consumes the authenticated-marker cap into the clear session. Neither ordinary pinned bytes nor raw decoded fields have an FS authenticate/mutation call. If the existing active view is Ready, the UI retains `Enter Game` and adds `Retry`, `View Details`, and `Discard Pending Import`; discard uses the separate confirmed-cleanup authorization and revalidates active state. Without an existing Ready view, the startup gate stays closed.

The publish state machine is `Prepared -> Publishing -> Committed`:

- the complete proposed generation, all group receipts, and its catalog are durable and fully revalidated before `Prepared`;
- `Publishing` performs only the atomic replacement of the small active-generation pointer;
- the previous immutable generation remains the rollback snapshot and is never modified;
- any synchronous failure before pointer replacement leaves the previous pointer authoritative; a failure after replacement is resolved from the pointer and journal epoch;
- startup recovery inspects unfinished journals before readiness checks;
- recovery either keeps/restores the previous pointer or confirms the complete proposed generation; it never guesses per group;
- a truncated, checksum-invalid, or path-invalid journal enters the fixed-name fail-closed recovery decision below and preserves both generations plus staging; startup may continue only if the independently authenticated active pointer and everything it references pass that decision, otherwise the gate remains closed; an unknown newer journal version always reports the update-required state;
- old generations are garbage-collected only while holding the import lock, after the committed generation, every receipt, active view, and a later cold-start post-commit validation pass; the newest valid rollback generation is retained until then.

Recovery is mandatory and cannot be cancelled by the UI. The lifecycle token is observed once immediately before one-shot recovery completion; after that checkpoint, candidate validation plus repair validation and the single lease-bearing repair publication use `CancellationToken.None` under the original monotonic deadline and clock. Each user import/resume and each startup validation attempt starts exactly one `IosImportEnvelopePolicyV1.WholeValidationTimeout` deadline from one injected monotonic clock. Candidate/repair validation, streamed materialization, `Prepare`, recovery completion, `Publish`, its sole post-switch validation, rollback/convergence, and final static preflight receive that unchanged deadline value and exact clock reference; no phase starts, refills, extends, value-copies onto another clock, or substitutes the budget. Validation returns a one-shot `RetailValidatedCandidateInput` binding the exact validation, source reference, nullable source-pending ID, exact nullable preserved-active snapshot reference/validation identity, and the exact borrowed operation identity owned by the live lease; repair returns a one-shot `RetailValidatedRepairInput` binding the exact active snapshot/validation identity, plan, validation, and same lease-owned identity. Prepare accepts only those wrappers, requires `ReferenceEquals` with the supplied lease before I/O, and never accepts separable authority components. The store accepts only that exact candidate or repair wrapper plus its live lease, remeasures the wrapper-bound storage plan, queries initial free space under its own pinned root, and mints a one-shot admission already bound by reference to wrapper/store/root/acquisition epoch/operation; no planner or caller supplies capacity or census scalars. Prepare consumes rather than binds it. A successful Prepare privately carries that consumed admission with the exact `StoreIdentity + RootIdentity + OperationIdentity`, process-lock lease, deadline, clock, and prepared root. Prepared has no component getters, general Take, copy/repack constructor, or replacement inputs; its sole `PreparedMintToken` owns the complete private state, atomically transitions once to the private `PreparedPublicationSession`, and Publish's first action forwards `TryConsumeFor` the exact store/root, so cross-store/root, alias, repack, null/default token, or double publication fails before I/O. After the first durable recovery mutation, deadline/cancellation no longer interrupt mandatory convergence. A successful repair publication is the terminal retail validation for that generation and is never followed by another recovery completion or active-catalog open. The final static-resource preflight alone observes the original lifecycle token again after durable recovery convergence. A process kill at any generation materialization, journal flush, receipt/catalog flush, pointer swap, post-commit validation, garbage-collection boundary, or outer-reset marker/rename/purge/inner-lock-unlink boundary must converge according to its own closed table on a later launch. This avoids modifying the mounted generation when adding one optional group while preserving atomicity across Base and Maps. Partial Yuri content is never committed. A failed map transaction cannot damage Base archives.

Cold-start retail recovery is a two-stage ownership protocol so recovery and normal startup do not hash the same candidate twice. The begin stage holds the importer lock, authenticates and pins only pointer, journal, catalog, receipt, root, and candidate identities, mints one fresh validation identity per snapshot, and performs no archive/map content read, publication, quarantine, garbage collection, or pointer mutation; abandoning that session has zero persistent effect. After the coordinator starts one deadline, captures the build identity, derives each candidate's pure expected contract, and constructs the required dispatcher, the one-shot completion stage validates each exact candidate at most once through the active-catalog opener. Candidate completion has four explicit states: Ready, RepairRequired, Invalid, and Inconclusive. Only stable complete validation proving bad content is Invalid and may occupy an invalid cell in the closed recovery table. Timeout, operational/lifecycle/dispatcher/I/O failure, callback exception, illegal tuple, wrong identity, final handle drift, or awaited pre-mutation cleanup failure is Inconclusive and returns `RecoveryFailed` with zero pointer, journal, quarantine, garbage-collection, or pending-consumption mutation. RepairRequired and Inconclusive are never collapsed into Invalid. The final deadline check occurs immediately before the first durable recovery mutation: expiry there remains zero-mutation Inconclusive, but after crossing that boundary neither deadline nor cancellation may interrupt mandatory rollback, journal/pointer convergence, parent sync, or capability cleanup; timeout becomes a reported outcome only after one durable table-authorized state is reached. For Ready candidates, completion awaits reverse release of all unselected leases, reauthenticates the pinned identities, applies the closed recovery table, performs any required non-cancellable pointer/journal convergence, transfers the selected Ready lease and its exact snapshot identity without reopening or rehashing it, and releases the process lock before returning. If recovery instead returns RepairRequired, the coordinator acquires one exact new repair lease, borrows its operation identity into `ValidateRepairAsync`, has the same store mint admission under that live lease, and passes only the bound repair wrapper plus that lease/deadline/clock/admission into one generic repair publication under the same build identity, dispatcher, and `CancellationToken.None`; Prepare rejects a non-`ReferenceEquals` wrapper/lease identity before I/O. That publication performs the repaired generation's sole post-switch active-catalog open. Published transfers its exact lease and Ready identity directly to static preflight; no fresh recovery session or second hash follows. RepairRequired, Invalid, or Inconclusive post-switch results remain distinct, roll back according to the publication table, asynchronously release provisional ownership, and stop the attempt. `RecoveryFailed` retains its zero-durable-mutation meaning only for failures before a recovery mutation boundary; it never relabels a repair publication that already performed rollback writes. The selected lease then undergoes the single static-resource preflight without holding the recovery lock; failure releases every owned capability and cannot forge Ready.

Direct ActiveOpen is exactly five-state. Ready owns authenticated Active+Ready+Readiness; RepairRequired owns Active+Readiness+Repair; Missing owns nothing; Invalid always owns a stable typed failure and may additionally own the exact authenticated Active+five-key Readiness pair needed for optional-group diagnostics/reset UI, but never Ready or Repair; Inconclusive owns only its operational failure and never an Active or Readiness pair. Every other tuple is unconstructible.

Prepared publication has no internal repack seam: the uniquely held `PreparedMintToken` owns the exact store/root/operation state and its one-shot `TryConsumeFor` alone may invoke the private `PreparedPublicationSession` constructor; Prepared only forwards that call. The store-minted admission token has the analogous sole consume edge to the private `PreparedSpaceAdmission` constructor. Compile-graph/source tests require each constructor to have exactly its declaration and corresponding token-consume reference, and runtime tests reject null/default/reflection construction, retained aliases, and second consumption before I/O.

A checksum/path-invalid journal is never parsed for paths or operations. It is resolved only by the fixed `publish.journal` token after Store has minted a live quarantine authorization bound to that exact inode and the complete reference set. Fixed-entry deletion is two-phase: only the authorization's private session lets the adapter choose q, rename and sync both parents; the returned `RetailQuarantinedEntry` must itself atomically create a private purge session. A crash-left q is reminted only after fixed enumeration plus live exact lease/operation, no-follow grammar/type/inode, closed recovery kind, and fresh authenticated active/pointer/journal/pin/reference-set checks. There is no caller q token, ordinary-entry quarantine, path delete, or ordinary/cap-only purge.

Whole-root reset is a separate outer-parent authority because a directory cannot be renamed into its own descendant. Opening the adapter pins the exact outer parent, fixed importer leaf, and root inode. Before any marker/root/sibling inspection, every Open/reset/convergence attempt non-blockingly acquires the true OS lease on the fixed outer-parent owner-only no-follow regular file `.retail-import-reset.lock`; first creation is parent-synced, the file is never renamed/purged, and a contender mutates nothing. After separate destructive confirmation, Store mints one root-bound authorization carrying its exact constructor-owned fault injector by reference. That authorization must atomically `TryConsumeFor` the exact Store/root/live inner lease into `ConfirmedResetSession`; only the session may enter root quarantine. The adapter chooses an unused immediate sibling `.retail-import-reset-q-{nonzero-guid:N}` and first durably writes the fixed sibling marker `.retail-import-reset.transaction`. Its V1 form is exactly 86 bytes: ASCII `NHRT`, version byte 1, state byte `Prepared=1|Renamed=2`, 32 lowercase-ASCII nonce bytes, unsigned little-endian 64-bit source-root device and inode, and SHA-256 of the preceding 54 bytes. No path is stored: the destination is derived only from the authenticated nonce. The adapter rejects symlink/type/identity/cross-volume/self/descendant drift, atomically renames and parent-fsyncs the root, durably advances the marker to Renamed, invalidates the old store, and transfers outer lease plus exact injector into `RetailQuarantinedRoot`. That cap must atomically create the private root-purge session before purge and marker removal. Existing `Open` evaluates the exhaustive marker/root/sibling table before creating or trusting a root: Prepared with source present completes rename; Prepared with only the exact sibling proves rename happened; Renamed with the exact sibling, including arbitrary partial purge and a missing inner lock, completes purge; Renamed with neither clears the already-finished transaction; both present, wrong identity/type/volume, or an unjournaled sibling fails closed; torn/checksum/illegal state is `RecoveryFailed`; version greater than 1 is `UpdateRequired`. No caller or publish journal supplies a parent, leaf, destination, session or injector, and a new store opens only after convergence. Six live process-kill failpoints cover Prepared-marker flush, rename+parent flush, Renamed-marker flush, pre-purge, quarantined inner-lock unlink+directory sync, and marker-clear+parent flush; ordinary restart convergence uses the disabled injector and does not inject a second crash. This transfer adds no field or constructor parameter to Task 6's frozen nine-parameter adapter and uses no static or `AsyncLocal`. If the active pointer, referenced generation, catalog, and receipts independently pass complete validation, that pointer remains authoritative and startup continues with a warning. If they do not, the UI offers that confirmed `Reset Imported Content` action and returns to Missing; it never follows journal data or touches external selections. A publish journal with a newer unknown version instead reports `Update NUKE HOUR to finish recovery`; reset remains a separately confirmed escape hatch. Tests cover every outer-reset table row, corrupt journal plus valid pointer, corrupt journal plus invalid pointer, future versions, identity/sibling/self-descendant rejection, crash at each reset boundary, and proof that outside files remain byte-identical.

Outer-reset convergence is linearized across processes only by that fixed outer-parent `.retail-import-reset.lock`, never by the recorded root's or sibling's inner `import.lock`. The outer descriptor is retained continuously from before marker/root/sibling read through Prepared/rename/Renamed, arbitrary partial purge including inner-lock unlink, marker clear, idempotent fresh-root creation, creation and verification of its new inner lock, and final parent sync. The complete tuple is re-read under the lease before every mutation; a contender returns Busy/Failed with zero mutation. `Renamed` with an exact partially purged sibling reconstructs the one-shot root capability from the checksummed marker and sibling inode and finishes. `Renamed` with neither recorded root nor sibling uses atomic marker clear, create-if-absent `mkdir`, and no-follow identity verification; the ordinary absent-marker/absent-root row uses the same idempotent creation path. No stale observation may purge a newly created root, choose or guess a nonce, clear a replacement marker, or replace a peer's fresh root. Two-process tests pause at all six reset failpoints and every table row, kill after inner-lock unlink, and prove one old-root purge, one durable convergence, identical outside sentinels, and no concurrency gap when the sibling inner lock no longer exists.

`Prepared` with neither its recorded root nor marker-derived sibling is `RecoveryFailed` with zero mutation because it cannot prove both rename and purge; `Renamed` with the recorded root present but sibling absent is likewise `RecoveryFailed` and never treats a stale or freshly recreated root as the quarantined inode.

Receipts are stored outside the mounted retail file namespace and contain only canonical relative names, group, size, SHA-256, the schema-reserved recognized-edition field (always null in V1), profile ID, manifest-contract digest, filename-catalog digest, validator/converter/map-format versions, map UID/output digest, transaction epoch, validation result, and commit identifier. They contain no external paths or account data.

Readiness, validation, publication, recovery, artifact, verified metadata, and lease-bearing result objects are authority, not caller-populated records. They are sealed get-only nominal types with private constructors and internal exact-state factories, defensive immutable collections, closed legal tuples, and explicit one-shot take/dispose or awaited async-release semantics where ownership moves; there is no public constructor, `init`, record-copy/`with`, subclass, mutable-array, direct ownership getter, or discarded cleanup path that code outside Game/RA2 and the trusted iOS composition TCB can use to manufacture a success state or leak a capability. Codec-only receipt/journal DTOs likewise use internal validating construction. The typed generation/pending outcome is permanently named `RetailGenerationImportResult`; it remains distinct from the characterized legacy raw-path `RetailImportResult`, which is removed with that legacy importer surface rather than renamed or reused. The exact engine-owned cross-assembly projection DTOs `Gen2OverlayResolution`, `VerifiedMapPlayerMetadata`, and `VerifiedMapPreviewMetadata` are the sole public bounded-data exception: each has a private constructor and one public validating `TryCreate` factory, defensively copies collections, and can produce no receipt, root, artifact, snapshot, lease, Ready, remote verified metadata, or other authority. Engine entry/publisher/result factories stay internal and are reached only by the exact audited iOS bridge call edges. The whole friend assembly can technically access those members; evaluated compile-graph plus final-IL allowlists, mutation tests, finished-app/IPA image identity, and signing gates make the exact production call graph a release invariant rather than pretending CLR friend access is per type. RA2's friend set remains exactly `OpenRA.Test` and `OpenRA.iOS`: the crash harness is never added as a friend, but references the public test-only synthetic driver compiled into `OpenRA.Test`, which alone invokes RA2 internals. Ordinary request/limits/UI input may retain public validating constructors, but cannot produce trusted evidence. A verified contract alone exposes no engine-identity conversion: only the internal factory that pairs it with the exact store-minted Ready and requires the same validation-identity object may derive the generic identity and opaque runtime authorization; the public identity struct is a handshake scalar, not authority. Public runtime-map consumers cannot invoke recovery with a caller-built scalar. The runtime-map generation store's raw Application Support root constructor is internal to the iOS composition/test friend boundary, exposes no root getter, and cannot be invoked by an arbitrary mod consumer with a lookalike path.

Startup uses the receipt as a cache, not blind proof. Every cold start recomputes SHA-256 for active top-level retail archives and maps even when size and timestamps match. Only matching hashes plus matching profile/manifest/catalog/validator versions may skip the expensive nested structural pass. A missing file, digest mismatch, or mount failure invalidates and structurally revalidates the affected item/group. The global gate closes only when Base is invalid, a mount required by the newly selected profile is invalid, or no Base-compatible map remains. Corrupt/unmountable Yuri, music, and individual maps are quarantined from the view and the profile is recomputed as described above. Required mount exceptions are no longer swallowed; only explicitly validated optional groups may be omitted.

## Progress, cancellation, retry, and lifecycle

The import core reports a typed immutable progress snapshot:

- phase: PreparingSources, Discovering, Planning, Copying, VerifyingActiveHashes, ValidatingEnvelopes, ValidatingArchives, ValidatingAudio, ConvertingMaps, LoadingMaps, DownloadingMap, ValidatingDownloadedMap, SelectingProfile, ValidatingMounts, CheckingRuntimeResources, Committing, or Recovering;
- current sanitized filename or content group;
- completed and total items;
- completed and total bytes when meaningful;
- integer percentage only when the denominator is known.

Provider preparation, discovery, structural validation, conversion, profile/mount checks, runtime-resource checks, and recovery use an indeterminate indicator rather than a fabricated percentage. Copying and active SHA-256 verification report real completed/total byte progress when their denominators are known. Unknown-length provider streams remain indeterminate while enforcing a hard running byte cap and repeated free-space checks.

The coordinator owns one cancellation token source for the active transaction. During cancellable discovery/copy/validation/conversion work, all import/start/retry buttons are disabled and only Cancel remains enabled. `Committing` and `Recovering` are non-cancellable: they show the exact phase, reason, and indeterminate progress, with no action button. Cancel, backgrounding, picker access loss, or application interruption never publishes partial content and never removes the previous Ready set.

Retry is semantic:

- if a complete staged snapshot remains and the failed operation is safely repeatable, retry resumes validation/conversion without re-copying;
- if staging is incomplete because source access was lost, the action is `Choose Again` and reopens the picker;
- `Check Again` revalidates active content and is not presented as retrying an import.

Retryable snapshots are sealed by the canonical pending artifact/hash document above, have the 8 GiB size cap and derived seven-day expiry, and remain outside the active namespace. A complete sealed snapshot is self-contained and survives release of the source security scope; a partial snapshot is never retryable. Cancel cleanup of unpublished data is allowed only before non-cancellable commit/recovery and only through Store's pending-cleanup authorization. Startup runs journal recovery before validating any retry snapshot; incomplete s and malformed, expired, orphan, or confirmed-discard p are never directly deleted. Under the process lock, a complete reference-set proof authorizes same-nonce s-or-p to t, and only the resulting cleanup cap/session may purge it; a crash-left cleanup t is freshly reauthorized from the complete reference set and is never treated as consumption.

Space planning outside Store is advisory and produces no admission census. The exact `RetailGenerationStore` accepts only the exact `RetailValidatedCandidateInput` or `RetailValidatedRepairInput` plus its live lease, re-enumerates the wrapper-bound sealed source, other pending data, rollback generation, proposed payload/conversion plan, and metadata plan, and privately mints a one-shot `RetailPublishSpaceAdmission` bound by reference to wrapper/store/root/acquisition epoch/lease-owned operation identity and measured identities. `observedRetainedOnDisk` records already allocated sealed/pending/rollback bytes for drift detection but is never charged again against the current free-space sample. `peakIncrementalFromCheckpoint` contains only the maximum additional proposed payload, conversion, metadata, and atomic-temporary bytes that may coexist from that checkpoint. Initial admission requires current free space to cover only checked peak incremental plus the exact 512 MiB margin. Store meters every subsequent write and rejects component under-report or identity drift before pointer work. After the durable `Publishing` journal and immediately before any pointer temporary/write/rename, the consumed prepared session performs a parameterless pinned-root recheck against only the still-unwritten incremental peak plus the same margin; already written and retained bytes are not double charged. Both production probes pass their private measurements to one private pure checked-arithmetic helper; it cannot query a root, mint/consume authority, expose census/capacity, or accept caller capacity through a production API. Reflection tests cover negative/overflow and `-1`/exact/`+1`, while source/final-IL gates require both probes to call it. Admission has no public scalar getter, public/caller-capacity/scalar factory, clone/repack, or retarget path; equal numeric measurements from another wrapper fail.

Admission is intentionally non-persistent: after a crash, recovery may confirm proposed only when the authenticated pointer already targets its exact generation/epoch/commit. If a Publishing or Committed journal names a nonactive proposed generation, recovery never advances the pointer. Under one lock and only through Store-minted q authorization/session, it durably retires proposed plus journal while preserving any exact seal. A pointed Ready remains `KeptPrevious` or `ReadyWithCorruptJournalWarning` even when the nonpointed proposed candidate is RepairRequired. A pointed RepairRequired is also authority: recovery retires only nonactive proposed/journal state, preserves its pointer/generation and exact Active+Readiness+Repair tuple, and returns `RepairRequired`, so Task 14 can start a clean repair publication transaction. Stable Invalid or absent pointed state supplies no authority: exact seal yields existing `Missing` only after invalid pointer/generation retirement, while no seal yields `ResetRequired`. Inconclusive alone remains zero-mutation RecoveryFailed and cannot authorize any row. A kill inside authorization/q rename/remint/purge/journal retirement is followed by two fresh starts: the first completes exactly that row, and the second sees no stale journal plus the same Ready/RepairRequired pointer, absent pointer plus exact seal, or clean reset state. No launch reuses the dead admission or loops the branch. Generation materialization and pointer publication stay on one volume; a cross-volume destination is rejected rather than silently downgraded to non-atomic copy.

Before normal game startup, foreground activation may resume the import UI but first runs non-cancellable journal recovery and then recomputes readiness. After `Game.InitializeAndRun` begins, foreground activation may only resume UIKit and an incomplete pending copy; it cannot recover/publish active content, switch profile, convert maps, reconstruct `ModData`, or re-run the startup gate. Security-scoped access is held only while enumerating and copying the selected sources and is always released exactly once.

## iOS/iPadOS user experience

The startup wizard is shown when minimum playable content is missing, invalid, or recovering, or when a quarantined/pending import requires an explicit Retry, Details, or Discard decision. When the active RA2 Base, one Base-compatible map, and the runtime-resource preflight remain Ready, that pending-decision state keeps `Enter Game` available alongside its resolution actions; it never demotes the verified active catalog. With no pending decision, a Ready active catalog enters the main menu normally. Optional Yuri/music omissions are shown without blocking Base.

The page is a safe-area-constrained `UIScrollView` containing:

- a title and concise legal-content explanation;
- separate Base, RA2 Music, Yuri, Yuri Music, and Maps status rows;
- current phase, real progress, and sanitized failure details;
- state-specific actions rather than six permanently visible buttons.

Compact landscape iPhones use a one- or two-column action grid; iPads may use wider columns. Every action is at least 48 points, supports Dynamic Type, wraps without truncation, and remains reachable at supported accessibility sizes.

Recommended actions by state are:

- Missing Base/Maps: `Choose Files or Folder`, `View Licenses`;
- Importing: `Cancel` only;
- Recoverable failure: `Retry` when valid staging exists, otherwise `Choose Again`, plus `View Details`;
- Failed pending optional import with active Ready content: `Enter Game`, `Retry`, `Discard Pending Import`, and `View Details`;
- Base Ready, optional content missing: `Enter Game`, `Import Optional Content`;
- Fully Ready: `Enter Game` and `Manage Game Content`.

Optional content remains accessible after startup through an iOS-only `Manage Game Content` action from the main menu. It reuses discovery, copying, envelope validation, and the transaction format, and it is unavailable during a match. The first release never replaces `Game.ModData`, converts retail maps, changes the active profile, or mutates retail filesystem mounts while the game process owns a loaded mod. The only runtime publication exception is the separately isolated `VerifiedRuntimeMapStore` snapshot protocol above; it cannot alter retail readiness or the profile. An in-game retail-content selection is sealed as a pending transaction and displays `Restart to finish import`; the next application launch runs recovery, profile/map validation, and activation in the pre-game gate. There is no in-process mod hot reload in this release.

English and Simplified Chinese strings follow the existing System/English/Chinese preference policy. Raw exceptions and full external paths are diagnostic-only.

## PublicClean runtime-resource boundary

Import correctness and PublicClean runtime closure are separate gates with deliberately different status in the current authorized milestone.

The importer owns only player-provided retail data and converted player maps. It must not solve missing engine/project resources by copying retail data into the app bundle or by weakening the public manifest.

The current PublicClean target is diagnostic-only and is not launched. Its source, configuration, metadata, build, bundle, provenance, and no-retail audits prove that the artifact contains none of the 17 unreviewed iOS runtime-profile resources, that the closed configuration contract maps the first missing fixed resource to typed `RuntimeResourcesMissing`, and that no call edge reaches retail-content selection, importer/coordinator construction, the active catalog, runtime services, wizard actions, or `Game.InitializeAndRun`. There is no alternate Enter Game edge or compile-time bypass. These are static source/configuration and bundle-absence proofs only: this milestone does not claim that PublicClean executed a preflight, returned an error code, displayed UI, or produced any other runtime observation.

The frozen historical 580-error PublicClean fixture remains known-failure diagnostic history. The current milestone must introduce no new error relative to that exact baseline and must bundle no retail bytes, but neither an unchanged count nor a typed fail-closed result is called PASS, Ready, playable, releasable, or suitable for an IPA.

After the Personal milestone, a separate focused design must close the known clean-bundle requirements, including shaders, required common/system packages, public-safe UI/load-screen/font resources, shell-map or no-shell-map startup behavior, the global MIX filename database when required, and removal or replacement of `$ts`/TS chrome dependencies that are not part of the public RA2 runtime. It must reintroduce explicitly reviewed PublicClean profile resources and implement and test a real consumer for PublicClean mode, or replace the inert `Engine.PublicClean` argument with an explicit build-selected runtime manifest; the current argument alone is not treated as an active safety boundary.

That design must not solve the problem by adding the entire TS mod or blanket-allowing current RA2 `bits/uibits`. The current bundle is missing renderer GLSL, fonts, load-screen/UI resources, a usable shell map, and the TS asset-browser dependency is reachable from the RA2 manifest. Existing `.shp` resources are rejected by the public audit before manifest classification and therefore require a provenance-approved replacement format or a separately justified audit-policy change. A minimal project-owned shell map may be used only after its source and assets pass the public manifest.

The importer preflight is a static bundle/file/mount contract only. In the Personal artifact, a successful result permits the full importer/readiness flow to continue; it still cannot claim that renderer, fonts, load screen, shell map, or skirmish runtime behavior has been exercised. For the current unlaunched PublicClean artifact, audits inspect only the source/configuration mapping and exact bundle absence described above; they make no claim that `RuntimeResourcesMissing` was returned or observed at runtime. Renderer and real skirmish claims require the future clean-bundle runtime smoke gate. The Personal UI calls a successful static result `Runtime resources present` rather than `App runtime verified`.

Acceptance for the current publishable milestone requires:

- Personal importer end-to-end Ready with legally owned external content;
- a fresh registered-device Personal Ad Hoc install that reaches a real two-player skirmish; and
- the separate PublicClean diagnostic checks above, without treating them as PublicClean runtime acceptance.

The Personal App and IPA release audits are new zero-error gates. The historical PublicClean 580-error fixture remains diagnostic history and is never redefined as a passing baseline.

No PublicClean source artifact, app, or IPA is described as playable until reviewed profile resources are restored and that future build passes the same complete importer/readiness gate, clean-bundle runtime smoke, signing audit, and fresh-device skirmish acceptance. This restriction does not relabel or block the separately authorized registered-device Personal Ad Hoc milestone.

## Security and legal boundaries

- No retail game asset is committed to Git, bundled in the app, uploaded by the app, downloaded by the retail importer, or written outside the private importer/runtime-map roots. Provider materialization and the separately bounded community-map service retain the explicit exceptions defined above.
- The importer never executes selected content or loads user DLLs, native libraries, scripts, or arbitrary mod rules.
- Directory-discovered executable and irrelevant files are ignored, never copied.
- Direct executable selections, executable magic under accepted extensions, unsafe map packages, symlinks, and traversal are rejected.
- All writes resolve under fixed support/map roots and reject escapes before I/O.
- Every staging, pending, immutable generation, catalog, receipt, retained rollback generation, converted-map, and legacy-migration destination is marked `NSURLIsExcludedFromBackupKey = true` and uses `NSFileProtectionCompleteUntilFirstUserAuthentication`. Creation, coordinated copy, rename, recovery, and migration reassert and verify both resource properties; inability to establish them is a typed storage-policy failure before publication.
- Logs contain group, basename, byte count, digest when appropriate, and error code, but no cloud path or account data.
- The app states that users must import content from a legally owned copy and that NUKE HOUR is not affiliated with or endorsed by Electronic Arts.

## Delivery decomposition

The current Personal deliverable and the later PublicClean/public-release work are separated into the following bounded milestones:

1. discovery, content model, validator contracts, and synthetic fixtures;
2. verified Base and Base+Yuri runtime profiles;
3. incremental transaction journal, receipts, recovery, and progress/cancellation;
4. reusable map conversion/load validation and correct map destination;
5. iOS coordinator/state machine and responsive UI;
6. in-game optional-content staging and next-launch activation;
7. Personal private-fixture and physical-device import acceptance;
8. Personal About/legal/source surface, AOT/bundle/signing audit, and registered-device Ad Hoc IPA production;
9. current PublicClean no-retail/provenance/build audit, exact historical 580-error diagnostic preservation, and static proof of the fail-closed configuration mapping and unreachable Personal graph, with no launch or runtime observation;
10. future separately reviewed PublicClean runtime-resource/profile closure and the same full importer, runtime-smoke, device-skirmish, and zero-error release audits;
11. after the Personal closure forms its exact final clean source commit, an optional separately and directly authorized source-only publication may provide the immutable corresponding-source URL required by the Personal distribution gate; this action is external to the plan and authorizes no app/IPA/PublicClean release;
12. only after the future PublicClean closure and separate authorization, any broader tag/release action and matching public app release.

Each milestone remains reversible and keeps unrelated user files, retail content, credentials, build artifacts, and historical engine patches out of commits.

## Non-goals for this design

- No network download of retail assets and no `Original Demo Assets` package; the separately bounded existing community-map download path is not a retail-content source.
- No direct ISO, CAB/HDR, ZIP, RAR, or 7z extraction in the first release.
- No desktop importer redesign.
- No executable mod/plugin import.
- No arbitrary map scripts or embedded rule overrides in PublicClean.
- No silent conflict resolution or destructive replacement of valid content.
- No in-process profile switch, map conversion, or mod hot reload after normal game startup.
- No claim that the current PublicClean provenance baseline is a passing runtime build.
- No claim that the current PublicClean artifact runs the importer, is Ready/playable, passes runtime smoke, or is an installable release IPA.
- No GitHub publication except the narrowly scoped, separately authorized Personal corresponding-source prerequisite above, and no public app/IPA/PublicClean release until the importer and future PublicClean runtime-resource gates pass; the registered-device Personal Ad Hoc IPA is not a public release.
