# macOS 双语语言切换器设计

## 目标

将 macOS 启动器左下角现有的紧凑下拉语言菜单替换为清晰、易点击的双语切换控件，同时保留首次启动时的系统语言自动识别。

## 范围

- 仅修改 macOS Python 启动器及其相关自动化测试。
- 不改变 iOS、Android 或游戏引擎内的语言选择界面。
- 不调整启动页、侧边导航、版本号或其他控件的位置与视觉层级。

## 交互设计

语言控件固定在左侧栏底部、品牌页脚上方，结构为：

```text
[ ‹ ]  简体中文  [ › ]
[ ‹ ]   English   [ › ]
```

实际界面只显示当前语言对应的一行。左右按钮都将当前语言切换到另一种语言；采用两个按钮是为了形成明确、对称且容易点击的切换方式，而不是表达超过两个选项的方向顺序。

首次没有有效语言偏好时，继续使用 `System` 作为内部偏好，并根据 macOS 系统语言解析为简体中文或英文。用户第一次点击任一切换按钮后，写入明确的 `zh-CN` 或 `en` 偏好。手动选择会持久化；启动器立即刷新，游戏在下次启动时使用新语言。

## 视觉设计

- 控件宽度扩展到侧边栏可用宽度，不再使用 56 像素下拉徽章。
- 左右按钮使用不小于 32 像素的可见尺寸和完整高度点击区域。
- 当前语言文字居中显示，不出现下拉箭头或弹出菜单。
- 默认状态使用深色表面、浅色文字和低对比度边框。
- 悬停与键盘聚焦状态使用 NUKE HOUR 金色强调色，但不改变周围控件。
- 保持左下角品牌页脚完整可见，控件与页脚之间保留 8 像素间距。

## 状态与错误处理

- 无效或缺失的已保存值按 `System` 处理。
- 系统语言无法识别时继续回退到英文。
- 持久化失败时保留当前界面和原始设置文件，不留下临时文件，并显示现有启动器错误反馈。
- 切换过程中不重建顶层窗口，不改变当前页面和用户尚未保存的其他设置。

## 测试与验收

- 布局测试验证控件位于左侧栏底部、页脚上方，宽度足以容纳英文标签。
- 语言策略测试验证首次启动仍按系统语言解析。
- 交互测试验证左右按钮都能从中文切换到英文、从英文切换到中文。
- 持久化测试验证点击后写入明确的 `zh-CN` 或 `en`，且不破坏其他设置。
- 源码契约测试验证不再创建语言 `Menubutton`、下拉菜单或可见的 `System` 选项。
- 运行 macOS 启动器相关测试，并在实际启动器窗口中检查中文和英文两种显示状态。

## 非目标

- 不增加第三种可见语言状态。
- 不增加旗帜图标或依赖国籍表达语言。
- 不修改游戏资源、本地化文本内容或多人联机协议。
