# OpenRA iPad 全屏与菜单修复设计

## 目标

让 OpenRA/RA2 在 iPad 上以独占、横向全屏显示，并首先复用现有 OpenRA 菜单。菜单必须按实际 iPad drawable 尺寸布局，不再以独立的小 SDL 窗口或错误的竖向尺寸显示。

## 方案

1. iOS 启动时由 UIKit 创建应用根控制器，但不保留可见的宿主内容层。
2. OpenRA 的 SDL iOS 窗口以全屏标志创建；UIKit 的 SDL 视图因此占用应用内容区。
3. iOS 平台窗口以 SDL 返回的实际 drawable 尺寸同步 `windowSize`、`surfaceSize` 与 viewport，避免使用启动前的虚拟桌面尺寸。
4. 仅允许左右横屏，并隐藏状态栏以获得稳定的游戏区域。
5. 通过模拟器验证启动页、初始设置页及主菜单的全屏尺寸和可见性。

## 回退策略

若全屏且尺寸同步后，原生 OpenRA 菜单仍无法完成进入单人游戏的交互，才增加 UIKit 原生启动菜单。该菜单只承担“继续/单人游戏/设置/退出”的入口职责，实际对局与规则、资源、渲染仍全部交给现有 OpenRA 引擎。

## 错误处理与验证

全屏创建或 drawable 尺寸为零时，保留错误日志并不启动渲染。验收以 iOS 模拟器截图、引擎无未处理异常日志、以及可进入实际 OpenRA 菜单作为证据。
